# 微信小程序：能不能做、怎么做、怎么上

判断一个小程序产品是否可行、把 PRD 落成代码、走到上架收费。任何评估类请求，**先过合规闸门，再谈技术**。

## When to Use

- 用户说「做个小程序 / 创建小程序 / 游戏小程序 / 能不能做」或丢来一份产品需求书要评估。
- 要注册、认证、备案、选类目、接支付、提审、发布小程序时。
- 边界：公众号发文走 `wechat-official-account`（那个技能管登录/排版/发表）；本技能管小程序本体（开发 + 合规 + 上架）。两者合规门槛完全不同，别把公众号的结论套到小程序上。

## 铁律：先合规体检，再写代码

小程序能否落地，90% 由三道行政闸门（类目资质 / 备案 / 支付通道）决定，代码只占 10%。任何「评估可行性」的请求，**先过门槛清单并给出结论，再谈技术方案**。顺序反过来会给出误导性的乐观答案。

## 第 0 步：分清「小程序」还是「小游戏」

用户口语里的「游戏小程序」歧义极大，先用产品实质判断、并显式说明：

- 普通小程序（工具/内容/社交/娱乐测试）：无需版号。
- 小游戏类目 + 有内购或广告变现：必须有**游戏版号**，要求企业主体（个人、个体工商户都不行）、注册资本 ≥100 万、ICP 资质，全流程 3–6 个月。
- 判断口径：功能主体是「记录 / 查询 / 计算 / 结果展示」→ 普通小程序；有玩法关卡、实时对战、虚拟道具 → 小游戏。不要因为用户说了「游戏」二字就把一个工具型产品判进小游戏类目，但要把两条路的代价都摊开讲。

## 第 1 步：门槛清单（逐条给结论）

1. **类目与资质** —— 最大不确定性，先定类目再谈别的。
2. **小程序 ICP/APP 备案** —— 硬门槛，未备案不能上架；需真实主体 + 法人/负责人核验。
3. **支付通道** —— 虚拟商品（解锁功能、订阅内容、充值、道具）必须接入小程序虚拟支付，不得用普通微信支付、不得引导到 H5/公众号/个人号收款。
4. **主体与经营范围必须匹配类目**。
5. **名称/品牌** —— 全网唯一 + 商标风险。
6. **内容与话术禁区**。

具体数字（费率、结算周期、限额、资质、成本、周期）一律查 `references/compliance-and-launch-gates.md`，**不要凭记忆报**。

## 第 2 步：技术方案默认值

- **原生小程序（WXML/WXSS/JS）+ 微信云开发**（云函数 + 云数据库 + 云存储）。理由：免自建服务器、免域名备案、云函数里调三方 API 不受域名白名单限制。不引三方框架，审核与性能最稳。
- **不照抄 PRD 的技术选型。** 常见过度设计：PostGIS / Postgres 空间索引（MVP 量级直接在云函数里算 Haversine + 区间重叠）、自建订单表 + 普通微信支付回调（虚拟商品必须走虚拟支付的道具直购）。
- **受控接口**（`getLocation` / `chooseLocation` / `onLocationChange`）需在小程序后台申报用途并审核。降级方案：云函数调腾讯位置服务做地点搜索 + `map` 组件展示，不申请敏感接口——审核摩擦更小，也符合「不追踪」定位。
- **海报/动画**：Canvas 2D 绘制海报 → 保存相册/转发；动画用 CSS，不上 3D（低端机流畅优先）。
- **服务端一律不信任客户端**：`user_id`、`payment_status`、`unlocked` 都必须服务端判定；虚拟支付用「发货推送 + 主动轮询」双通道 + 查单兜底，订单幂等，绝不能只信客户端支付成功回调（回调会丢）。
- 用户自定义文本（昵称、会话名、留言）走 `security.msgSecCheck`。
- 数据生命周期要**真实现**（到期删除/匿名化、日志不记明文坐标+身份组合），不是只写在用户协议里；测试环境用虚拟数据。

## 第 3 步：先做不需要任何审批的可玩版本

备案/认证/支付开通是周级到月级周期，别让用户空等：先用云开发**免费环境**把核心闭环在真机跑通给用户看，再决定要不要投行政成本。**这条要写进评估结论的建议里。**

- **用户已有小程序时，直接用他现成的 AppID 开工**，不要走测试号——测试号绑不了他自己的云开发环境，而 1.0 依赖云环境。AppID 还没拿到就先写代码，`project.config.json` 的 `appid` 留占位，拿到再填。
- **类目/备案/认证只挡「正式发布 + 收钱」，不挡开发版/体验版内部试玩**。所以「先把 1.0 跑起来」和「办行政」是两条并行线：开工不要卡在资质上，反过来也别对用户说「做好就能上线」。
- 用户中途改主意（「先用我现有小程序跑 1.0，后面再升级」）是最省时间的顺序，不要坚持先做完评估/注册再动手。
- 具体代码骨架、云函数设计、脱离云的本地测试法、跑起来的分步操作与坑，见 `references/build-playbook.md`。

## 评估交付物怎么写

- 落盘成 markdown 备忘到 `~/AI工作台/<项目名>/`（Chris 的项目目录习惯），聊天里给 `MEDIA:` 路径 + 一段口播式结论，不要把全文粘进对话。
- 结构：① 一句话结论（技术上能不能 + 卡点是什么）② 本机现状（已装/未装/待用户动作）③ 技术可行性表 ④ 风险按严重度排序 ⑤ 成本与周期表 ⑥ 三条路线对比（个人主体·工具类目 / 企业科技主体·工具类目 / 社交类目重合规）⑦ 建议的下一步 + 需要拍板的决策项 ⑧ 来源链接。
- 关键数字必须带官方来源链接（`developers.weixin.qq.com` 优先）；报不出来就不写。
- 需要用户拍板的事只列 3 个左右；结尾明说涉及营业执照、法人核验、付款的动作会先确认（Chris 的钱/合同/印章/删除类动作是审批红线）。

## 运营状态怎么汇报

用户问「运营/上线准备得怎么样」时，给一张**带责任方**的状态表，不要写散文：

| 事项 | 现状 | 卡点 / 需要谁 |
|---|---|---|

- 逐条覆盖：AppID、微信认证、ICP 备案、服务类目、主体、云开发环境、开发者工具。
- 每条标清谁来推动：我负责的（代码/测试/部署/提审材料）自己消化掉；需要用户的（扫码、执照、法人核验、付款）单独列出，并说明**它在哪一步才真正卡人**（发布/收钱时，不是开发时）。
- 有实测卡点就直说，别含糊成「待确认」：例如读小程序后台要扫码登录 `mp.weixin.qq.com`，登录态跨调用会掉，「登录 + 读状态」必须在一次操作里做完。

## 主体选择（Chris 的集团语境）

- 货代/贸易主体（利顺国际物流、东方卉达）经营范围对不上「工具/社交/娱乐」类目 → 类目审核容易被拒。
- 优先用经营范围含「技术开发/技术服务/软件开发/信息技术服务」的科技主体（如五州信联供应链科技），或新设一个小微主体专承载产品。
- 个人主体是最快的验证路径（工具类目 + 个人虚拟支付），但不能开普通微信支付，很多类目也不开放，且有月收款限额。

## 坑

- **代码写好 ≠ 能收钱**：没有已认证的合规主体，虚拟支付开不了。技术进度和收款能力是两条独立的线，评估时要分开讲。
- 别把「社交类目的 ICP 经营许可证」当默认必须项：双人邀请制、无陌生人匹配、无公开 UGC 的产品按「工具」申报通常不需要；但审核按**实际功能**判，所以第一期界面与文案一律不出现交友/匹配/社交字样，降低被判社交的概率。反过来，真要做成社交平台，就要预备 ICP 许可证的注册资本门槛与 1–3 个月周期。
- 小程序名称全网唯一，用名句/热词命名大概率被占；注册前先查重并备 2–3 个候选（可加品牌前缀）。含营销词/热词的名称会被要求补商标等证明。
- 「相遇/缘分/指数」类娱乐化结果的文案必须标注仅供娱乐，并避开「算命/占卜/测算」措辞——平台没有占卜类目，这类内容会被拒。
- iOS 与 Android 的支付结算差异巨大（佣金 + 45–60 天结算），定价前先算这笔账。
- 云开发免费环境只在体验阶段免费，发布后要买基础套餐。
- 微信客户端 ≠ 微信开发者工具：开发工具是独立 App，要单独安装、扫码登录，并给运营者微信号开开发者权限（成员管理里加）。
- **集合名必须加项目前缀**（如 `zl_`）：用户的小程序往往已有自己的云数据库，直接用 `users/records/sessions` 这类通用名会和既有数据撞名。动他现有项目的任何配置文件前先备份。
- **装开发者工具别自己硬抓下载直链**：官方下载页是 JS 渲染，`curl`/正文提取拿不到 `.dmg`，官方跳转接口回的 302 不带 `Location`。用浏览器打开下载页取链接，或直接请用户点一下装好（一步就完）——别在这上面连烧几次工具调用。

## 验证

- [ ] 评估类交付：三道闸门 + 类目 + 主体 + 名称 + 支付通道逐条有结论；关键数字有官方链接；一句话结论在最前面。
- [ ] 开发类交付：算法**先在本地测试里跑过**（纯函数从云函数 export 出来，测试里用 `Module._load` 把 `wx-server-sdk` 换成空壳 → `node tests/xxx.js`，不连云、不装依赖），再真机跑通核心闭环（邀请 → 双方录入 → 计算 → 结果展示）；受控接口已申报或有降级方案；支付走虚拟支付且服务端幂等校验。
- [ ] 上线前：备案通过、类目与经营范围一致、隐私保护指引已声明所采数据、名称过审、测试与生产数据分离。
