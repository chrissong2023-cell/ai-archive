# 贸易报价单与代理协议

For any outward commercial document in Chris's freight/trade business:
运费清关报价单、进口代理协议、贸易代理/付汇协议、补充协议、报价修订。
The deliverable is a finished draft the client could receive after Chris's
review — not a skeleton, and never a document that quietly drops the
compliance terms.

## When to Use

- Chris 说「出一份报价单 / 协议 / 合同给客户」——运费、清关、进口代理、贸易代理、付汇、保险。
- 已有报价要改价格结构、加费率项（如通道费）、换签约主体、补合规条款：改生成脚本重跑，不要手改文件。
- 客户方回稿要改条款：沿用同一份 clause library，只改数字、主体、时限。
- **采购合同（我方是买方）**：供货商拿他家的《销售合同》《采购协议》模板要我们签（GPU/内存/硬件/大宗货），
  走同一套第 8 步评审流程，重点换成买方视角的六处必改项 + 缺项六项 + 签署前对手方核验（见第 9 步）。
- **合同前阶段的报价资料包（我方是买方）**：供货商发来《采购函》/《采购意向书》+《库存清单》/《报价单》+ 配置单
  （BOM，常是内嵌图片）要我方签字盖章，此时对方还没给合同。产物是一份《资料审阅》：缺附件、两套付款路径冲突、
  单位与配置口径、主体身份矛盾、合规红线一次摊开。清单与方法见 `references/supplier-quotation-package-review.md`。
- Not for：内部报表、公众号文章、给同事的内部说明（各走自己的技能）。

## 交付物与格式（硬性偏好）

- **交付只发纯文本**：`.md`（必要时附 `.txt`，UTF-8）是聊天里唯一的交付物。
  Chris 明确说过「不要发我二进制文件」——`.docx` 只在他要盖章/打印时另存到同目录并在回复里给路径，
  默认不作为交付物发送。文本版用 `docx` 技能的 `scripts/docx_cjk.py export`（同一份内容导出，不另写一份）。
  `.docx` 仍是内部事实源（改稿改脚本重跑、导出文本），只是不进聊天。
- 目录 `~/AI工作台/<项目名>/`，命名 `<文件类型>-<签约主体>-<项目>-<YYYYMMDD>.<ext>`。
- 生成用 python-docx 脚本（样式/表格/页脚页码），中文字体必须先过
  `docx_cjk.py fonts`，生成后跑 `docx_validate.py` 必须 `"ok": true`。
- 交付回复：`MEDIA:<绝对路径>` 列全部文件 → 改动/要点（贴报价单正文，协议正文不铺开）
  → 合规与风险提示 → `【 】` 待确认清单。不复述生成过程。

## 流程

1. **取事实**，缺项用 `【 】` 占位并在回复里列清单——绝不自己编客户名、数量、货值、日期。
   需要：签约主体（哪家集团实体承担哪一段）、客户全称、最终用户、货物名称/型号/数量/单台货值、
   起运地与入境口岸、交付地、费率结构（服务费/保险费/通道费）、税费承担方、付款条件、账期。
2. **合规先过一遍再动笔**：货物是 AI 芯片/GPU/两用物项/受控物项时，先查许可要求并把风险讲清楚，
   同时在报价单写「报价前提＝许可单证齐备」、在协议写合规专条。见
   `references/controlled-goods-licensing.md`。合规不通过时，出稿的价值是让 Chris 看到风险，不是把单做成。
3. **报价单**：抬头表（编号/日期/有效期/致客户/币种）→ 服务范围逐条 → 费用明细表（项目/计价单位/单价/说明）
   → 报价说明。费用表把税费和代垫费用单列一行标「实报实销、凭据结算、须事前书面确认」；合计行只放服务费。
   报价说明固定覆盖：计价结算、付款条件、有效期、不含项、保险口径、批次假设、「以协议为准」、报价前提、税费与发票口径。
4. **协议**：条款顺序固定——货物与项目信息 → 服务范围（含转委托关联公司）→ 费用与结算 → 乙方义务与单证
   → 税费承担与不垫付 → 贸易代理与付汇 → 合规与出口管制 → 保险 → 交付风险索赔 → 责任限制与免责
   → 保密 → 期限与终止 → 违约责任 → 适用法律与争议解决 → 其他 → 签署页 → 附件（单证清单、操作确认单）。
   措辞从 `references/agreement-clause-library.md` 取，只改数字、主体、时限。
5. **费率条款先问基数**：千分之几是按人民币购汇金额还是美元金额，两者差 7 倍以上（0.8% × RMB 216,000
   ≈ RMB 1,728 vs USD 30,000 × 0.8% = USD 240）。汇率基准（付款日中行现汇卖出价 / 双方锁汇）同样要写明。
   任何示例金额必须标「示例汇率、以实际为准」，别把假设写成承诺。
6. **生成 + 自检**：读回数字（单价、费率、示例金额、合计、时限）核对；
   增删条款后重排编号并全文搜一遍「第 X.X 项」交叉引用（加一条就会把后面的编号全挤位）。
7. **改稿**：改生成脚本再重跑（脚本是唯一事实源，`build_*.py` → docx → export txt/md），
   不要手改 .docx 或只改文本版——两份会分叉。
8. **评审对方发来的模板/回稿**（客户或合作方拿来他们的合同，要求我们签）：出一份
   《评审意见与回稿修改建议》文档，结构固定——文件概况表（主体/编号/结算方式/争议解决/来源）
   → 总体判断（结论先行，第一句就说这份合同偏谁、能不能签、必须改几处）
   → 「无需修改、属行业惯例」列表（避免把整份合同都标成问题）
   → 必须修改条款对照表（# / 条款原文要点 / 风险 / 建议措辞，措辞要能直接贴进回稿）
   → 建议补充的缺项 → 与现有报价单·协议的衔接（环节 / 承接主体 / 依据文件三列表 + 现金流提示）
   → 签署前书面确认清单 → 外部事实附注（把查到的公开事实和来源写进去）。
   重点扫：责任限制与赔偿口径（高值货按「同类产品成本价」赔＝远低于货值）、留置与变卖、
   罚款归属是否以我方过错为前提、保险义务归属、发票税率表是否覆盖进口环节税费与 13% 凭证、
   结算方式与授信额度、争议解决地（异地法院 vs 仲裁）、以及一切《合规准则》《承诺书》附件——
   那类不可撤销、有效期延续数年的单方承诺，是把上游许可责任转移到我方的常见手法，必须改。
   对方声明自己「仅承担形式核对义务」时，用同一表述要求对等，比自创措辞好谈。

   **评审对方发来的采购合同（我方为买方）**时，固定扫六处，按杀伤力排序，逐条给出能直接贴进回稿的措辞
   （六处对照表 + 缺项清单在 `references/supplier-purchase-contract-review.md`）：
   ①**付款方式**——卖方模板几乎都写「签合同后 N 日内付全款，收款后 N 个工作日内发货」，大额采购＝无担保的全额预付，
   收钱方跳价/少发/不发时买方当场没有反制手段。改成「分批交货、分批验收、分批付款，设单批金额上限，
   或由卖方提供银行保函/履约保证金/第三方资金监管」。
   ②**验收期限**——「当场检查验收 + 3 个工作日异议 + 逾期视为合格」对批量货（几百张卡要逐张上机）不可执行，
   签了等于放弃质量索赔权。改成「交付后 7 个工作日逐张上机验收」，并保留隐蔽瑕疵（伪造序列号、非原厂维修、
   芯片掉包、内部拼装）更长的主张期。
   ③**保修口径**——非正规渠道货写「12 个月原厂维保」＝实际无保修（品牌方会拒保）。改成
   「无法享受原厂保修时由卖方承担同等或更优保修责任 + 维修时限 + 逾期按日补偿」。
   ④**违约金量级**——1‰/天 覆盖不了「一天一价」商品的跳价损失（¥565 万 × 1‰ × 15 天 ≈ ¥8.5 万，
   而该商品一周可涨 12%）。改成卖方逾期 3‰/天，并加「卖方不能交付须承担买方替代采购的涨价差额」。
   ⑤**争议管辖**——「起诉方所在地」易被认定无效，且把买方拖到卖方城市应诉。改成买方所在地法院。
   ⑥**反常条款**——「扫描件/传真件与原件不一致时以扫描件为准」必须反过来写「以双方签字盖章的原件为准」。
   缺项必补：货物来源合法性保证与全额赔偿、序列号清单附件（逐张 SN 交付时签认）、13% 增值税专用发票与开票时限
   （验收合格后 N 个工作日）、假货/翻新赔偿倍数、质保金（预留 5–10%）、单批金额上限或担保。
   谈判让步顺序：**付款方式 > 验收期 > 发票 > 假货赔偿 > 来源担保 > 管辖**。对方连「分批交货＋见货付款」都不接受时，
   结论是放弃这笔交易，而不是继续改条款。

9. **签署前对手方核验（我方要付钱时，必做，并把结果写进评审文档单列一节）**：
   ①统一社会信用代码先过校验位——`python3 scripts/uscc_check.py <代码>` 打印校验位是否通过、行政区划码、
   主体标识码前缀（M 开头多为 2015 年三证合一后登记）；校验位不通过直接停。
   ②对公账户户名核验——在手机银行输入账号看户名回显，或先汇 1 元核对户名与合同主体是否完全一致；
   合同里的账号排版（空格、分段）不要照抄，以银行回显为准。不一致一律不付。
   ③工商四项——注册资本与实缴、经营范围是否覆盖该品类、经营异常/被执行/涉诉、股东与法人。
   ④凭证——营业执照、法定代表人身份证明、授权委托书、一般纳税人资格、货物来源凭证（上游采购发票/
   海关单证/代理授权链）、货物实拍（包装 + 序列号特写）。
   企查查/天眼查/爱企查这类站点需登录或注册，脚本抓不到快照：把这四项列成清单交给 Chris 或 Nova 当场查
   （手机 App 最快），或让他截图后回来判断——**抓不到就写「未能核实」，不要为了填表而编造工商结论**。
   公开信息零足迹（无官网/无招聘/无新闻/无中标）本身就是结论，要写进报告。

## 发出前：第二意见审查（推荐，但只做生成不做事实源）

对外报价/协议/英文信发出前，先用另一个模型做一次红队挑刺，能抓到自己看不见的漏：

```bash
python3 ~/.nova-tools/second_opinion.py --role redteam --file ~/AI工作台/<项目>/<文件>.md
python3 ~/.nova-tools/second_opinion.py --role contract --file <合同>.md
python3 ~/.nova-tools/second_opinion.py --role editor  --file draft.txt --lang en
python3 ~/.nova-tools/second_opinion.py --status        # 看是否已配 key、本月花费
```

- **脱敏是自动的**：邮箱/手机号/卡号会被替成 `[EMAIL]`/`[PHONE]`/`[CARD]`；**金额、型号、编号保留**——否则审查没意义。
  整份客户名单、原始合同 PDF 不上传；只传片段或已脱敏正文。
- **它只提意见，不定事实**：金额、交期、型号、条款号一律回到本地知识库/原件核对；它张冠李戴时可以完全不采纳，并写明为何不采纳。
- 有月度预算闸门（默认 $20），超过自动拒调；没配 key 时降级为“可粘贴包”（我出提示词 + 材料，Chris 自己贴 ChatGPT，再把回答贴回来）。
- 审查结果存档在 `~/AI工作台/00-总控/第二意见/`，定稿时回来对照一次“哪些意见入了、哪些没入、为什么”。

## 常设业务规则（每次适用）

- **零自动发送**：报价单/协议只出稿。对外发送、盖章、开通权限一律先经 Chris 确认；
  钱、合同、印章、删除类动作零自动。
- **不垫付税费**：法定税费（关税、进口环节增值税、消费税等）由委托方承担并先付，
  条款必须明写「甲方不予垫付、不代垫」，并写明未及时付款导致的滞报金、仓储费由谁承担。
- **合规优先于利润**：发现出口管制/转运规避/制裁风险先提示，不给规避方案，
  不写换品名、改原产地、双清包税绕许可之类的表述；宁可丢单。
- **付汇必须真实贸易背景**：报价单和协议都要写明合同/发票、提单/运单、报关单三单一致可追溯，
  并保留中止付汇、解除协议、向主管部门报告的权利。纯资金通道（钱走一条线、货走另一条线）不接。
- **主体选择**：利顺国际物流=货代/运输段；海南瀚宇供应链科技=进口贸易代理/购汇付汇；
  五州信联供应链科技=供应链科技；Dandelion Global(HK)=境外贸易/资金平台。
  合同主体不确定时先用最贴近业务的那家并在回复里点明，跨主体用「转委托/关联公司」条款衔接，
  不要拆成多份合同。
- **账期口径**：仅双方均为 WCA 会员才谈 30 天；新客户、易腐货、代理付汇类全额预付。
- 进口增值税凭证口径（双抬头海关缴款书 / 我方开 13% 专票给最终用户）写进协议并加
  「以最终用户所在地税务机关规定及实际办理结果为准」的兜底句。

## Pitfalls

- **只交 .docx** = 一定被退回要文字版；反向也成立：**主动发 .docx 会被当成「二进制的文件」直接退回**——默认只给 `.md`/`.txt`（见「交付物与格式」）。
- **中文字体**：python-docx 只设 `font.name` 不够，会给中文回退字体；必须给 run 和 style 的 `rPr` 写
  `w:rFonts/@w:eastAsia`（用 `docx` 技能 `scripts/docx_cjk.py fonts`）。
- **表格默认无边框**，费用/条款表要设 `Table Grid` 并显式给列宽。
- **条款编号会错位**：插一条就整段重排，并同步改「按第 3.x 项支付违约金」这类引用，否则协议自相矛盾。
- **币种混装**：美元服务费 + 人民币税费/通道费同表时逐行标币种，合计行不要混币。
- **商业条款别替客户定**：付款比例、争议解决（贸仲 vs 法院）、协议期限给推荐值并标 `【 】`，
  让 Chris 拍板——这几项他一定会改。
- **交付地/流向别猜**：口岸、交付地、货物流向这类信息客户口述常含糊（例如只说「从雄安出来」），
  写成 `【 】` 并在回复里单独问，不要按自己的理解锁死服务范围。
- **对方模板里的单方承诺附件**（合规准则、进出口合规承诺书、反商业贿赂承诺）：一般不摆在正文里，
  一签就把出口管制/制裁/申报合规的主体责任全揽过来，且不可撤销、有效期延续多年。逐句看这些附录，
  别只审正文。
- **卖方模板上的「含税」不等于合规**：货源没有合法进口凭证时，卖方开出的 13% 专票是无真实进项支撑的票，
  受票方承担进项被追缴、罚款乃至涉虚开的风险。买方视角必须把「来源合法性保证 + 因来源问题被查扣的全额赔偿」
  写进正文，并索要上游采购发票/海关单证/代理授权链，别满足于「能开票」。
- **注册资本远低于合同金额**（七位数以上交易、卖方注册资本小且实缴不明）＝履约能力不成比例：
  要求法定代表人/实际控制人出具连带责任承诺，或把交易拆成小批见货付款。
- **批量货的「当场验收」条款一律要改**：几百张卡/几百件货不可能当场逐件上机检验，签下即放弃质量索赔权。
- **对方模板常预填签署日期与自家合同编号**（批量群发的痕迹）：签署前把日期改为实际日期、甲方信息与
  清单（型号/数量/单价/序列号）填全，空白清单不能先盖章。
- **资料包里的配置单是图片**：`read_file` 抽 docx/xlsx 只得正文，内嵌的 BOM/规格表图片会静默丢失（正文只剩一行
  「参考配置单」）。必须解包取 `word/media`、`xl/media` 再用视觉逐行读（配方见 references/supplier-quotation-package-review.md），
  否则配置对比全是空的。
- **附件不存在时不要评价条款**：正文把价格/配置/付款全指向「附件一」而附件没给时，这份函不产生任何可执行权利义务——
  先索要附件，再逐条评审。
- **别把「现货/期货」当同一笔价**：报价单常只给现货现款（CAD、1 天），而采购函写的是期货 8–16 周 + L/C，
  两者价格与对手方都不同；混着算出来的成本一定错。
- **中文量词单位要算两种读法**：「（美金，万）」读成万美金还是万人民币，40 台级订单差 5 倍以上；
  两种口径都算出来交回 Chris 定，别自己选一个。
