# 卖方报价资料包评审（合同前阶段）

适用：对手方发来的**是一组资料而不是一份合同**——采购函/采购意向书（要我方签字盖章）、库存清单/报价单（表格）、
配置单（BOM，常是内嵌图片）、交易流程说明。产物不是回稿而是一份《资料审阅》，作用是在动笔改合同之前，
把不可执行的空白、互相矛盾的口径、以及合规红线一次摊开，并把待确认项交回 Chris。

## 0. 先留档，再动手

微信/IM 收到的附件在临时目录（macOS 微信为
`~/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/<账号>/temp/drag/`），**会被清理**。
第一步 `cp` 到项目目录 `~/AI工作台/<项目名>/source/`，之后一律在副本上工作。

## 1. 把资料包拆开读全：图表里的配置单要单独取出来

`read_file` 能自动抽 docx/xlsx 正文，但**内嵌图片里的 BOM 表格抽不出来**——正文只会剩一行「参考配置单」。
硬件/大额货的配置单、规格表、报价截图基本都是图片，必须解包取图再喂视觉：

```bash
cd "$HOME/.hermes/cache/scratch" && mkdir -p probe && cd probe
cp "<原件>" a.xlsx && unzip -o -q a.xlsx && find . -type f | sort   # 看 xl/media/、xl/drawings/
# docx 同理：word/media/、word/document.xml、word/_rels/document.xml.rels
sed -n '1,20p' docProps/core.xml                                   # 谁做的、什么软件、最后修改时间
```

- 用 `vision_analyze` 对 `xl/media/*`、`word/media/*` 逐张读，明确要求**逐行读出 PN/描述/数量**，不要只问「这是什么」。
- 用 `r:embed="rIdN"` + `word/_rels/document.xml.rels` 定位图片在正文里的挂点，判断它是「附件一」还是随手贴的参考图。
- `docProps/core.xml`（作者、`dcterms:modified`）与 `docProps/custom.xml`（WPS/ONLYOFFICE 痕迹）能说明这份文件是从哪家的模板改来的；
  元数据/文件名里的收件人（「to X」）与正文抬头主体不一致时，问清 X 是中间人还是签约主体。

## 2. 报价数字：单位、档次、品牌三件事先锁死

- **单位**：中文量词口径（如「（美金，万）」）先按两种读法各算一遍（万美金 vs 万人民币），看哪种与
  「付款方式 / 交割速度 / 用途申报」自洽；把区间交给 Chris 定，不要替他选一个读法。数量×单价用 `execute_code` 算。
- **档次**：同名型号不同内存/容量/版本的价差可达数倍，报价单里的 `3T/4T` 必须落到具体 BOM 行。
- **品牌**：同档次不同整机厂（超微/技嘉/戴尔/华硕）不能直接比价，网络与扩展配置不同（见第 3 节）。
- **自校验**：拿「单台价差 ÷ 对应物料差」对量级（例：多 1TB 内存＝32 条，报价差 2 万美金 ≈ 20 美元/GB）。
  数量级对不上，说明价格口径读错或配置根本不对应。

## 3. GPU/服务器整机的规格口径（避免比错）

- **清单里的 `2T/3T/4T` 通常是系统内存（DDR5 RDIMM 总量），不是显存**：3T = 32×96GB DDR5-6400、
  4T = 32×128GB、H200 级整机 2T = 32×64GB。报告里点明这个口径，否则「3T/4T 差 2 万美金」会被当成显存差异。
- **HGX 8 卡整机的网络配置差异最大**：板载 8×ConnectX-8 800G（GPU fabric）+ 另配 DPU（BlueField-3 400GbE，存储/管理）
  与「另配 2×ConnectX-7 200G」是两档东西，在训练集群里不是差价问题而是能不能组网的问题。逐行对 PN 与数量。
- 其它必对：CPU 型号/TDP、电源（数量×瓦数，8 卡机常见 12×3000W）、系统盘与数据盘的容量与块数、
  网卡是否 Secure Boot / No Crypto 版本。
- 满配与裸配（内存数量 0）是两张价签，报价资料里常混着给，必须要求逐项标注。

## 4. 合同前阶段必查的缺项（比条款措辞更要命）

资料包常见形态是「正文指向附件、附件不存在」，此时这份函不产生任何可执行的权利义务：

- **附件是否真实存在**：正文写「见附件一《产品订货确认函》」「配置见附件」时，把附件找出来；附件缺位时
  价格/数量/型号/配置全为空，先索要附件再评审，别在空白上做措辞优化。
- **两套付款路径是否冲突**：期货（L/C、8–16 周）与现货（现款现货 CAD、1 天）常分别写在两份文件里，
  报价单只给其中一条。先问走哪条、各自对应什么价（两条路径价格不同）。
- **L/C 的交单单据清单**：没有单据清单的 L/C 银行无法审单＝不可执行。单据要落到具体名称（商业发票、装箱单、
  仓单/放货单、SN 清单、原厂证明、压测报告），并写清分批支取与每批发货量的对应关系。
- **验收判据**：只写「当场压测」不够——压测工具/时长/通过阈值（NCCL 带宽、GPU burn、显存 ECC、整机功耗）、
  验收天数、隐蔽瑕疵主张期。
- **SN 与原厂质保核验**：「原厂正品、原厂包装」是承诺不是证据。要求交付 SN 清单并在原厂渠道核验质保状态——
  灰市渠道下这是唯一有效的防改机、防拼装手段。
- **罚则、Incoterms 与风险转移点、保税仓货权**：写「罚则：无」＝买方零救济；交货地写「香港保税仓」却没有 Incoterms、
  没有仓单/放货/货权转移单，等于交付条件没写。
- **报价格式里的反常项**：「大小款拆分」（如 217+22，佣金单独走款）意味着发票金额与实际付款不一致，
  对 L/C 交单、香港主体入账、后续转售开票层层埋雷，必须问清佣金付给谁、凭什么名目。
- **卖方 KYC 要求与买方主体是否匹配**：要求「营业执照 + 当日资金证明」的卖方，对香港/境外主体怎么执行
  （注册证书 + 商业登记证 + 银行当日余额证明？）要先写清，否则锁货环节就卡住。

## 5. 主体与身份一致性（最常被忽略、后果最重）

对方模板里常残留上一手的主体口径，逐处核对并在报告里单列：

- 正文写「本人 / 以自然人身份签署 / 统一社会信用代码：不适用（自然人）」，而签署方是境外法人、签字人是 Director——
  **互相矛盾**，KYC、最终用户申报、L/C 交单都会卡在这里。
- 中文地址栏空、英文有值；电话模板残留别国号段（如 `+7`）＝整段从别处模板复制，主体信息必须全部重填。
- 页眉文件编号未填全（`P-2026|xx-xxx`）、中英文日期不一致（英文日期早于文件最后修改时间）都要点出来。

## 6. 合规红线：组合式痕迹要一次说破

单看每条都「算常见」，叠在一起就是规避特征：**自然人签署 + 虚拟币（USDT）付款 + 大小款拆分 + 用途勾「自用」+
最终用户/最终用途/最终目的地留空 + 价格或数量异常**。GPU/AI 芯片属美国 EAR 管制物项（ECCN 3A090 系列），
二手/现货不豁免，香港是敏感目的地。报告里按 Chris 的立场写：要么补齐真实最终用户与合规文件，要么不做；
**不给任何规避设计**。

## 7. 先查内部基准，再评价报价

对手方名、机型、单价基准先在自己的语料里搜一遍，别只凭外部行情下结论：

```bash
grep -rn -i "<对手方名>\|<机型>\|<GPU/内存型号>" \
  ~/.openclaw/workspace/knowledge/feed/extracted*/*.txt ~/.openclaw/workspace/knowledge/*.md \
  ~/.openclaw/workspace/memory/*.md ~/AI工作台 2>/dev/null | head -20
```

- 集团实签过的合同价（历史每台单价）是最硬的锚点：与当前报价并列，把倍数关系写进报告。
- 对方声称的库存量（如某机型 2000 台现货）要与自己的供应链认知对照，并索要仓单/库存照片/SN 段。

## 8. 交付
